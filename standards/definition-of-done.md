# Definition of Done

Задача завершена, коли виконано всі застосовні пункти. Пункт, який не стосується зміни, позначається в pull request як «не застосовно» з поясненням в одне речення.

Позначка **[авто]** означає, що пункт перевіряє конвеєр (hook або CI). Решту підтверджує автор і перевіряє рецензент.

## Поведінка

- [ ] Зміна реалізує вимогу або сценарій зі `spec.md`; у pull request вказано ідентифікатор (`FR-n`, `SC-n`).
- [ ] Реалізовано не лише успішну гілку, а й усі гілки збою, описані в сценарії.
- [ ] Зміну перевірено на запущеній системі (`make run`), а не лише тестами.

## Код

- [ ] **[авто]** Формат, лінтер і перевірка меж шарів проходять без винятків.
- [ ] Кожен `//nolint` має назву лінтера та причину.
- [ ] Залежності спрямовані так, як описано в `spec.md`; нової залежності між шарами чи сервісами не з'явилося без оновлення spec.
- [ ] Помилки обгорнуто з назвою операції; доменні помилки перекладено на коди відповіді в транспорті.
- [ ] Кожен новий виклик назовні обмежений у часі.
- [ ] У логах немає токенів, паролів і вмісту листів.

## Дані та повідомлення

- [ ] Зміна схеми оформлена новою міграцією з парою `up` / `down`; наявні міграції не редагувалися.
- [ ] Міграцію `down` справді запущено, і вона повертає схему до попереднього стану.
- [ ] Зміна даних і запис в outbox, який вона породжує, виконуються в одній транзакції.
- [ ] Нове повідомлення має контракт у `shared/contracts` і поле `RequestID`.
- [ ] Новий споживач ідемпотентний: повторна доставка того самого повідомлення нічого не ламає. Це перевірено тестом.
- [ ] Зміна контракту gRPC або повідомлення сумісна з попередньою версією або змінює обидва боки в одному pull request.

## Тести

- [ ] **[авто]** Усі модульні тести проходять із `-race`.
- [ ] Новий сценарій покрито модульними тестами: успішна гілка і кожна доменна помилка.
- [ ] Виправлення помилки супроводжує тест, який без виправлення падає.
- [ ] Моки згенеровано заново, якщо змінювався інтерфейс.

## Збірка та запуск

- [ ] **[авто]** Усі три сервіси збираються.
- [ ] **[авто]** Smoke-тест проходить: кожен сервіс відповідає на `/health`, а `/version` повертає хеш поточного коміту.
- [ ] Нову змінну середовища додано в `.env.example` і в таблицю README.
- [ ] Новий сервіс або залежність інфраструктури додано в `docker-compose.yml` із перевіркою готовності.

## Документація

- [ ] `spec.md` оновлено, якщо змінилися компоненти, зв'язки, дані чи сценарій.
- [ ] Є ADR, якщо зміна підпадає під умови з [adr-format.md](adr-format.md).
- [ ] README оновлено, якщо змінилися команди запуску, порти чи конфігурація.

## Здача

- [ ] Гілка та коміти названо за [git-workflow.md](git-workflow.md).
- [ ] **[авто]** CI зелений.
- [ ] Pull request описує, що змінено, навіщо і як перевірити.
- [ ] У `main` немає слідів незавершеної роботи: закоментованого коду, налагоджувального виводу, вимкнених тестів.

## Чому список саме такий

Частина пунктів з'явилася з помилок попередньої версії — кожну з них довелося виправляти окремим комітом `fix` уже після злиття:

| Пункт | Що довелося виправляти |
|---|---|
| Ідемпотентний споживач | крок активації підписки в сазі не перевіряв, чи його вже виконано |
| Межа спроб для повідомлень | повідомлення outbox, яке неможливо опублікувати, повторювалося нескінченно |
| Гарантія доставки | ретранслятор outbox вважав повідомлення надісланим, не чекаючи підтвердження брокера |
| Токени не в логах | токен було видно в записах журналу |
| Транзакція навколо зміни й outbox | компенсація саги виконувалася поза транзакцією |

Загальні пункти («код відформатовано», «тести проходять») автоматизовано, щоб на них не витрачалася увага рецензента. Увага потрібна там, де інструмент безсилий: чи збігається поведінка зі сценарієм і чи витримає система збій посеред операції.
